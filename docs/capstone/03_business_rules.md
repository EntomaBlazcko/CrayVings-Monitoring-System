# Deliverable 3 — Business Rules and Actors

Rules as enforced by `crayvings_monitoring_system_db` + the Express application
(verified against code and catalog, 2026-10-18).

## Actors

| Actor | Stored as | Capabilities |
|---|---|---|
| **Owner** | A normal `role = 'admin'` row whose username/email matches configuration — never stored as `'owner'` | Everything an admin can do, plus: cannot be archived or deleted (protected account), owner-only decisions (device config/hide, factory resets), bootstraps itself if no admin exists |
| **Admin** | `users.role = 'admin'` | Manage devices and thresholds/calibration, manage users (create/archive), manage SMS recipients, acknowledge alerts, view all logs, send SMS, read/act on dashboards |
| **User** | `users.role = 'user'` | Read dashboards, live data, charts, alert views; change own password; cannot manage fleet, users, or settings |
| **Device (ESP32)** | `devices` row + 64-hex `device_secret` (Bearer) | `POST /sensor` ingest (1 s cadence), `GET /status` health self-report (5 s), config-portal secret rotation with grace window |

## Business rules

| # | Rule | Enforced by |
|---|---|---|
| **BR1** | A tank is represented by exactly one device (1:1); `tank_name` / `tank_location` live on the `devices` row. No reading can exist without its device. | Table design + FK `sensors.device_id` (mandatory) |
| **BR2** | Every reading belongs to exactly one device; a device may have zero readings (registered but not yet deployed). Readings are retained for a limited window; the device registry is kept indefinitely. | FK `sensors.device_id`; retention purge (`SENSOR_RETENTION_DAYS`, default 30, `0` disables) |
| **BR3** | Thresholds exist in exactly one global row; a device may carry at most one override row, which takes precedence over global values for that device. | `CHECK (id = 1)` on `sensor_settings`; composite PK on `device_threshold_overrides` (0..1 per device); precedence in `getThresholdStatus` (server.cjs) |
| **BR4** | A failed sensor reading is stored as `NULL` — never `0`, never a sentinel number (because `0` is a physically plausible value for water level and ammonia). | Migration 022 dropped all fake defaults; ingest converts wire sentinels (`-1`, `0` for temperature) to `NULL`; UI renders `--` |
| **BR5** | Alert state is tracked per device **and** parameter (display keys `'Temperature'` / `'Water Level'` / `'Ammonia'`, exact CHECK domain). At most one row exists per pair; the row is upserted on state change with status `'good'` / `'warning'` / `'critical'` (or `NULL`), not appended. | Composite PK `last_alerts(device_id, sensor_key)`; `chk_lastalerts_sensor_key`, `chk_lastalerts_status` |
| **BR6** | Every alert evaluation is against effective thresholds: per-device override if present, otherwise global settings. Ammonia alerts fire both above `ammonia_max` **and** below `ammonia_min`. | `getThresholdStatus` (server.cjs) reading overrides then `sensor_settings` |
| **BR7** | An account passes through `active → pending_deletion → archived` (the CHECK domain also retains `deleted` for legacy rows; `archived` is the reversible **hide/archive** state). Archiving keeps all audit history and releases the username/email for reuse (partial unique indexes exclude archived rows), and follows a strict workflow: request → OTP mailed to the **owner** → verification → execution, each transition recorded in status history (`PENDING_OTP → EXPIRED / COMPLETED`). A separate explicit purge permanently removes an archived account; then `user_id` FKs go `SET NULL` while name snapshots keep the identity. | `chk_users_status`; `chk_deletion_requests_status`; partial uniques `WHERE status <> 'archived'`; `user_deletion_requests` + `user_deletion_request_status_history`; `ON DELETE SET NULL`; `POST /auth/users/:id/restore`, `DELETE /auth/users/archived/:id` |
| **BR8** | SMS goes only to numbers that are active **and** not archived at send time; every attempt (success or not) is recorded, with `status` bounded to `'queued'` / `'delivered'` / `'failed'` / `'capped'` (`capped` = circuit breaker opened) and ending in one of them. | Send query (server.cjs: `is_active AND archived_at IS NULL`); `chk_sms_logs_status`; circuit breaker `capped` state |
| **BR9** | Every `sms_logs` row must reference an existing recipient phone **at insert time**, but history must survive permanent recipient purges — therefore a trigger, not a foreign key. | BEFORE INSERT trigger `trg_sms_logs_recipient` raising `ERRCODE = 'foreign_key_violation'`; no FK on `recipient_phone` |
| **BR10** | Audit records must never disappear when the subject is removed: purging a user sets `activity_logs.user_id` and `user_deletion_requests.user_id` to `NULL` (ON DELETE SET NULL — identity kept in `user_name` / `user_username` snapshots); removing a device would set `system_logs.device_id` to `NULL`. Reading and alert FKs are deliberately `NO ACTION`: `sensors` / `last_alerts` rows refuse to lose their device silently. | FKs `fk_activity_logs_user`, `fk_user_deletion_requests_user`, `system_logs_device_id_fkey` = SET NULL; `fk_sensors_device`, `fk_lastalerts_device` = NO ACTION; snapshot columns |
| **BR11** | Operational data ages out on fixed windows (defaults: sensor readings 30 d, system logs 30 d, SMS 30 d, activity logs 90 d; `0` disables each purge), while **current** state (`last_alerts`, `devices`, `sensor_settings`) is never purged. | Retention job (server.cjs, `purge()`); no purge touches `last_alerts` / `devices` / `sensor_settings` |

## Footnote — why `owner` is not a `role` value

`users.role` is a CHECK-bounded domain of exactly `'admin'` and `'user'`
(`chk_users_role`). The owner identity is **derived at request time**:
`isOwnerUser()` (server.cjs:755–770) compares the session's username or email against
the configured `ADMIN_USERNAME` / `ADMIN_EMAIL` environment values and returns an
`owner: true` flag in API responses. Consequences worth stating to the panel:

- The owner row is structurally an admin (no special DB privileges to leak);
- renaming or repointing the configured owner does not require a data migration;
- protection checks (`owner` and the last remaining admin cannot be archived) are
  application-enforced by that same function (server.cjs:3510).

Table users {
  id int [pk, increment]
  name varchar(100) [not null]
  username varchar(50) [not null]
  email varchar(255) [not null]
  password_hash text [not null]
  role varchar(20) [not null, default: 'user']
  // CHECK (migration 024): role IN ('admin', 'user'). 'owner' is derived at
  // runtime by isOwnerUser() and never stored in this column.
  token varchar(255)
  // created_at/updated_at were the last naive columns here; migration 025
  // converted both to timestamptz (token_expires_at was converted by 005).
  created_at timestamptz [default: `now()`]
  updated_at timestamptz [default: `now()`]
  token_expires_at timestamptz
  status varchar(20) [not null, default: 'active']
  // CHECK (migration 024): status IN ('active', 'pending_deletion', 'deleted', 'archived')
  deleted_at timestamptz
  pending_deletion_at timestamptz
  pending_deletion_requested_by varchar(100)

  Note: 'Referenced by id from activity_logs.user_id and user_deletion_requests.user_id (migrations 019/020), and by username (soft reference) from several audit columns. Usernames can be reused after archiving (migration 006).'

  Indexes {
    (status) [name: 'idx_users_status']
    // Allows an archived account's username to be reused by a new account.
    (username) [unique, name: 'idx_users_username_active', note: 'PARTIAL: WHERE status IS DISTINCT FROM \'archived\' (migration 006)']
    (email) [unique, name: 'idx_users_email_active', note: 'PARTIAL: WHERE status IS DISTINCT FROM \'archived\'']
    // Session lookup on every authenticated request and SSE connect. Partial
    // because signed-out users hold a NULL token; status is in the key because
    // the guards match token AND status in one predicate.
    (token, status) [name: 'idx_users_token_active', note: 'PARTIAL: WHERE token IS NOT NULL (migration 017)']
  }
}

Table devices {
  device_id varchar(50) [pk]
  name varchar(100)
  is_active boolean [not null, default: true]
  created_at timestamptz [default: `now()`]
  last_seen timestamptz
  ip_address text
  tank_name varchar(100)
  tank_location varchar(100)
  last_health_seen timestamptz
  device_secret varchar(255)
  registered_via varchar(20) [not null, default: 'auto']
  ip_source varchar(10) [not null, default: 'auto']
  archived_at timestamptz
  archived_by varchar(100)
  // Secret rotation (migration 015). Of the four secret columns, the API only
  // ever projects the two *_rotated_at / *_prev_expires_at metadata fields.
  device_secret_rotated_at timestamptz
  device_secret_prev varchar(255)
  device_secret_prev_expires_at timestamptz

  // Check constraints (migrations 014 / 015):
  //   chk_devices_registered_via: registered_via IN ('manual','auto')
  //   chk_devices_ip_source:      ip_source IN ('manual','auto')
  //   chk_devices_archived_pair:   (archived_at IS NULL) = (archived_by IS NULL)
  //   chk_devices_secret_prev_pair:(device_secret_prev IS NULL)
  //                               = (device_secret_prev_expires_at IS NULL)
  //
  // idx_devices_device_id_folded is NOT listed: migration 014 creates it only
  // when case-variant duplicates block the unique index. It does not exist live.

  Note: 'Devices are archived (archived_at), not deleted. FKs from sensors and last_alerts therefore use the default NO ACTION.'

  Indexes {
    // 'esp32-01' and 'ESP32-01' collide. This is the UNIQUE guarantee, not devices_pkey.
    (`lower(device_id)`) [unique, name: 'idx_devices_device_id_ci']
    (archived_at) [name: 'idx_devices_archived_at']
    (device_secret) [name: 'idx_devices_device_secret', note: 'PARTIAL: WHERE device_secret IS NOT NULL']
    (device_secret_prev) [name: 'idx_devices_secret_prev', note: 'PARTIAL: WHERE device_secret_prev IS NOT NULL']
    (device_secret_prev_expires_at) [name: 'idx_devices_secret_prev_expires', note: 'PARTIAL: WHERE device_secret_prev_expires_at IS NOT NULL']
  }
}

Table sensors {
  id int [pk, increment]
  device_id varchar(50) [not null]
  // No DEFAULT since migration 022 (defect D1, fixed): a failed sensor is NULL,
  // which the CHECKs below accept — the old vestigial DEFAULT 0 was rejected by
  // chk_sensors_temperature_valid, so it could never legally fire anyway.
  temperature decimal(5,2)
  water_level decimal(5,2)
  // precision is (5,2), not (5,3) - verified against the live database
  ammonia decimal(5,2)
  // Raw HC-SR04 distance (migration 018). NULL = not reported by the firmware
  // or a failed sensor. A lossy percentage alone cannot be recalibrated later.
  water_distance_cm decimal(6,2)
  timestamp timestamptz [default: `now()`]

  // Range checks (migration 009). Each allows NULL - a NULL reading means the
  // sensor failed, which is recorded rather than rejected.
  //   chk_sensors_temperature_valid: 0 < temperature <= 100
  //   chk_sensors_water_level_valid:  0 <= water_level <= 200
  //   chk_sensors_ammonia_valid:      0 <= ammonia <= 1000
  //   chk_sensors_water_distance_valid (migration 018): NULL or 0 < water_distance_cm <= 400

  Indexes {
    (timestamp) [name: 'idx_sensors_timestamp']
    (device_id) [name: 'idx_sensors_device_id']
    (device_id, timestamp) [name: 'idx_sensors_device_timestamp']
    (device_id, timestamp) [name: 'idx_sensors_valid_readings', note: 'PARTIAL: WHERE temperature IS NOT NULL OR water_level IS NOT NULL OR ammonia IS NOT NULL']
    // Functional index (migration 016) for case-insensitive tank lookups in server.cjs.
    (`lower(device_id)`, timestamp) [name: 'idx_sensors_device_id_ci']
  }
}

Table sensor_calibration {
  device_id varchar(50) [pk]
  // Distance from the sensor to the water surface at MINIMUM fill (0%).
  empty_cm decimal(6,2) [not null]
  // Distance from the sensor to the water surface at MAXIMUM fill (100%).
  full_cm decimal(6,2) [not null]
  updated_at timestamptz [not null, default: `now()`]
  updated_by varchar(100)

  // Check constraints (migration 018):
  //   chk_sensor_calibration_span:  empty_cm > full_cm (the level formula
  //                                 divides by (empty_cm - full_cm))
  //   chk_sensor_calibration_range: full_cm >= 2 (HC-SR04 blind spot)
  //                                 AND empty_cm <= 400 (module ceiling)

  Note: 'HC-SR04 water-level geometry per tank (migration 018). device_id is the PK, so one row per device. Alert thresholds live in sensor_settings / device_threshold_overrides, NOT here.'
}

Table sensor_settings {
  id int [pk, increment]
  // CHECK (id = 1), migration 023: the singleton is enforced by the database,
  // not by convention. server.cjs inserts id = 1 with ON CONFLICT (id).
  // All six range columns are NULLABLE in the live database (defaults, but no
  // NOT NULL constraint) - verified against information_schema.columns
  temp_min decimal(5,2) [default: 20.00]
  temp_max decimal(5,2) [default: 31.00]
  water_level_min decimal(5,2) [default: 10.00]
  water_level_max decimal(5,2) [default: 100.00]
  ammonia_min decimal(5,2) [default: 0.25]
  ammonia_max decimal(5,2) [default: 1.00]
  // timestamptz since migration 025 (converted from naive timestamp)
  updated_at timestamptz [default: `now()`]

  Note: 'Global thresholds. Per-tank values live in device_threshold_overrides (NULL there = inherit from here). Not linked by FK.'
}

Table device_threshold_overrides {
  device_id varchar(50) [pk]

  water_level_max decimal(5,2)

// One row per state transition of a user_deletion_requests row. Created by
