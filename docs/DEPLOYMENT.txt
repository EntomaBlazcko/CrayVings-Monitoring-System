================================================================================
CRAYVINGS AQUACULTURE MONITORING - PRODUCTION DEPLOYMENT GUIDE
Free. No subscriptions. No monthly fees.
================================================================================

This guide walks through putting the dashboard + backend + database into
production for $0/month. It covers three ways to run it so you can pick the
one that fits what hardware/internet you have:

    Option A - Raspberry Pi on-site (best for a farm)
    Option B - Free cloud VM (Oracle Cloud "Always Free", $0 forever)
    Option C - A spare PC / the machine you already have

Everything in this guide is either already-free software, software with a
free tier that never expires, or services you already run (SMS via the
HttpSms app, email via Gmail's free "app password").

3. BEFORE YOU START (settings you will need to change for production)
================================================================================

The production setup differs from development in a few required ways:

  Required changes
  ----------------  ----------------------------------------------------------
  NODE_ENV          must be "production"
  DEVICE_SECRET     MUST be set. In production the server refuses sensor
                    POSTs without a matching X-Device-Secret header
                    (returns 503 if nothing is set).
  ADMIN_INITIAL_    Required on first boot so the owner admin is created
  PASSWORD          (exits with an error if unset on a fresh database).
  ALLOWED_ORIGINS   must include the public URL the dashboard is served on.
  VITE_API_BASE     must point at the public URL at BUILD time - the frontend
                    bakes this into the website when you run npm run build.

  Keep as-is
  ----------
  SMS (HTTPSMS_API_KEY / HTTPSMS_FROM)   points at your phone, no change
  SMTP (email fallback)                  Gmail app password, no change
  Port 3000                              fine to keep

4. OPTION A - RASPBERRY PI ON-SITE (RECOMMENDED FOR A FARM)
================================================================================

A Raspberry Pi is a tiny ~$100 computer that runs 24/7 next to your tank.
It talks to the ESP32 over your own WiFi, so it keeps working even when the
internet drops.

Hardware
--------
    * Raspberry Pi 4 (2GB+) or Pi 5 - or anything you already own
    * microSD card 32GB+ (or a USB SSD for reliability)
    * power supply + network (WiFi is fine; Ethernet is more reliable)

1. Flash the OS (one time)
    - Download "Raspberry Pi Imager" (free, raspberrypi.com/software)
    - Choose Raspberry Pi OS Lite (64-bit) - no desktop needed
    - Click the gear icon and pre-set:
        * enable SSH
        * username + password (write these down)
        * WiFi country/network + password
    - Write to the microSD card, plug it into the Pi, power it on

2. Find the Pi and log in via SSH
    On Windows, open PowerShell:
        ssh <username>@<pi-ip-address>
    Find the Pi's IP on your router's admin page, or run:
        arp -a
    (If you set a static DHCP reservation on the router, the address will
    never change - optional but recommended.)

3. Install Node.js
        sudo apt update && sudo apt install -y curl build-essential
        curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
        sudo apt install -y nodejs
        node -v        # should print v22.x

4. Install PostgreSQL
        sudo apt install -y postgresql postgresql-contrib
        sudo systemctl enable --now postgresql

5. Get the code onto the Pi
    Copy your project folder, or if it is in a git repo:
        sudo apt install -y git
        git clone <your-repo-url> aquaculture-dashboard
        cd aquaculture-dashboard
        npm install --omit=dev

    Then continue at section 7 (application setup). The rest is identical
    for all options.

5. OPTION B - FREE CLOUD VM (ORACLE CLOUD "ALWAYS FREE", $0 FOREVER)
================================================================================

Oracle gives away a small virtual computer forever: 4 CPU cores / 24 GB RAM
(Ampere ARM A1.Flex) inside their data center. Your system runs there over
the internet, so the ESP32 must reach it over the internet too.

1. Create an account (free)
    - Go to oracle.com/cloud/free, click "Start for free"
    - You must add email + phone + a debit/credit card for identity
      verification. Oracle will NOT charge it as long as you only use
      "always free" resources. (You can remove/keep the card.)

2. Create the VM (the free one)
    - Console -> Compute -> Instances -> Create instance
    - Shape: choose "Ampere - Arm" and tick "Always Free eligible"
      (default A1.Flex) - pick 1 OCPU / 6 GB RAM minimum
    - Image: Ubuntu 22.04 LTS (or 24.04 LTS)
    - Add your SSH public key (generate one on Windows:
          ssh-keygen -t ed25519
      then paste the .pub contents)
    - Create. Note the Public IP address (e.g. 146.56.xx.xx)

3. Open the firewall so the app + tunnel can get out (SPF/NAT checks aside,
   the always-free VM also routes outbound normally) and allow HTTPS IN:
    - Networking -> Virtual Cloud Network -> your subnet -> Security List:
        * Ingress rule: Allow TCP 3000 from 0.0.0.0/0 (temporary - you can
          keep it or drop it once the Cloudflare tunnel is up and restrict
          the app to the tunnel instead).

4. Log in over SSH
        ssh ubuntu@<your-public-ip>    # "ubuntu" or your chosen username

5. Install Node.js
        curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
        sudo apt install -y nodejs build-essential
        node -v        # v22.x

6. Install PostgreSQL and secure it
        sudo apt install -y postgresql postgresql-contrib
        sudo systemctl enable --now postgresql
        sudo -u postgres psql -c "CREATE USER crayvings WITH PASSWORD '<strong-password>';"
        sudo -u postgres psql -c "CREATE DATABASE crayvings OWNER crayvings;"

7. Get the code
        sudo apt install -y git
        git clone <your-repo-url> aquaculture-dashboard
        cd aquaculture-dashboard
        npm install --omit=dev

    Then continue at section 7.

    NOTE for Option B: the ESP32 posts to your server over the internet. In
    the firmware set SERVER_IP to your VM's public IP (or domain). The
    HttpSms/email alerts still work the same.

7. APPLICATION SETUP (SAME FOR ALL OPTIONS)
================================================================================

All commands below run inside the project folder.

1. Install dependencies
        npm install --omit=dev

2. Create the environment file

        copy .env.example .env          (Windows)
        cp .env.example .env            (Linux)

3. Edit .env and set the production values

        NODE_ENV=production

        # Database - point at the local Postgres you created
        PG_HOST=localhost
        PG_PORT=5432
        PG_DATABASE=crayvings
        PG_USER=crayvings
        PG_PASSWORD=<strong-password>

        # Device secret - REQUIRED in production. Same value goes into the
        # ESP32 firmware. Long random string, never share publicly.
        DEVICE_SECRET=<long-random-string>

        # Admin bootstrap (only used the first time)
        ADMIN_INITIAL_PASSWORD=<one-time-strong-password>

        # CORS - the public URL Cloudflare gives you (see section 9).
        # If you serve the dashboard from the SAME URL as the API, this is
        # mostly for safety; the dashboard itself is same-origin.
        ALLOWED_ORIGINS=https://your-dashboard.<something>.trycloudflare.com

        # SMS + email: leave your current working values (HttpSms / SMTP).

4. Build the dashboard (IMPORTANT: VITE_API_BASE must be the public URL)

    The frontend calls the API at a URL that is baked in at build time.
    Set it to the same public URL that serves the dashboard, then build:

        (Windows PowerShell)
        $env:VITE_API_BASE="https://your-dashboard.<something>.trycloudflare.com"
        npm run build

        (Linux)
        VITE_API_BASE="https://your-dashboard.<something>.trycloudflare.com" npm run build

    Output goes into dist/.

5. Run the database migrations (one time, in order)

        node db/migrations/001_user_deletion.cjs
        node db/migrations/002_owner_admin.cjs
        node db/migrations/003_sms_integration.cjs
        node db/migrations/004_sms_delivery.cjs
        node db/migrations/005_schema_consistency.cjs
        node db/migrations/006_archive_restore.cjs

    Each is idempotent (safe to run twice). The server also auto-adds a
    few columns/indexes on startup.

6. Start the server to test

        node server.cjs

    Expected log lines (last one = success):
        PostgreSQL connected
        Loaded delta-logging baseline for N device(s) from DB
        Server running on port 3000

8. SERVE THE DASHBOARD FROM THE EXPRESS SERVER (SMALL CODE CHANGE)
================================================================================

Today the backend (server.cjs) only serves the API; the dashboard runs on a
separate dev server. For production, make Express serve the built site too,
so ONE process + ONE port (3000) handles everything.

Add a small block in server.cjs, AFTER the API routes are declared (before
the "app.listen" at the bottom), roughly:

    const path = require("path");
    const distDir = path.join(__dirname, "dist");
    app.use(express.static(distDir));
    app.get(/^\/(?!api\/).*/, (req, res, next) => {
      if (req.path.startsWith("/api")) return next();
      res.sendFile(path.join(distDir, "index.html"));
    });

    // (adjust the "api" prefix to match however your routes are mounted;
    //  the goal is: static files from dist/ + SPA fallback to index.html,
    //  while /sensor, /auth, /analytics, ... keep answering as JSON)

After this change:
    - http://HOST:3000/ serves the dashboard
    - http://HOST:3000/sensor/latest etc still return JSON
    - No CORS problems, because the dashboard and API share one origin

Rebuild the frontend (section 7 step 4) and restart the server, then open
http://HOST:3000 in a browser and it should load the dashboard.

9. PUBLIC ADDRESS + HTTPS FOR FREE (CLOUDFLARE TUNNEL)
================================================================================

The Cloudflare Tunnel gives you a public https:// URL with no port
forwarding, no domain, and no subscription. Your server opens an outbound
connection to Cloudflare; nothing has to be exposed on your router.

You only need this if you want to open the dashboard from OUTSIDE your
network. On a purely local farm you can skip this section entirely and just
visit http://<pi-ip>:3000 from your phone on the same WiFi.

1. Subscribe nothing, just sign up
    - cloudflare.com -> Sign up (email + password, free plan)
    - Install "cloudflared" on your server:
        (Linux/Pi/VM)
        curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -o /usr/local/bin/cloudflared
        sudo chmod +x /usr/local/bin/cloudflared

        (Windows) download cloudflared-windows-amd64.exe from the same
        releases page and put it in a folder on PATH.

2. Authenticate
        cloudflared tunnel login
    - copy the URL it prints, open it in a browser, log in, pick your
      free account -> it downloads a cert file automatically.

3. Create the tunnel
        cloudflared tunnel create crayvings
    - note the tunnel ID (looks like a UUID) - write it down.

4. Define what it forwards (config file, e.g. /etc/cloudflared/config.yml)
        tunnel: <your-tunnel-id>
        credentials-file: /root/.cloudflared/<your-tunnel-id>.json
        ingress:
          - hostname: crayvings-dashboard.<something>.trycloudflare.com
            service: http://localhost:3000
          - service: http_status:404

5. Get a hostname on that tunnel (Zero Trust console)
    - dash.cloudflare.com -> Zero Trust -> Networks -> Tunnels
    - select your tunnel -> Public Hostname -> Add
    - subdomain: crayvings-dashboard
    - domain: pick a free `trycloudflare.com` or attach your own domain to
      the free Cloudflare plan (optional)
    - service: HTTP -> localhost:3000

6. Run it as a service so it survives reboots
        sudo cloudflared service install

7. Open https://crayvings-dashboard.<something>.trycloudflare.com
   You should see the login page with a padlock (HTTPS).

   Because you set VITE_API_BASE (section 7) to this same address, the
   dashboard talks to the API over the same secure address.

10. AUTO-START + RESTART (RUN FOREVER)
================================================================================

systemd (Linux - Pi and Oracle VM)

Create /etc/systemd/system/crayvings.service:

    [Unit]
    Description=CRAYvings Aquaculture Monitoring
    After=network-online.target postgresql.service
    Wants=network-online.target

    [Service]
    WorkingDirectory=/home/<user>/aquaculture-dashboard
    EnvironmentFile=/home/<user>/aquaculture-dashboard/.env
    ExecStart=/usr/bin/node server.cjs
    Restart=always
    RestartSec=5
    User=<user>

    [Install]
    WantedBy=multi-user.target

Then run:

        sudo systemctl daemon-reload
        sudo systemctl enable --now crayvings
        sudo systemctl status crayvings      # shows "active (running)"

Useful commands later:

        sudo systemctl restart crayvings     # restart the app
        sudo journalctl -u crayvings -f      # watch its logs live

PM2 alternative (if you prefer it on the Pi/VM)

        npm install -g pm2
        pm2 start server.cjs --name crayvings
        pm2 save && pm2 startup             # auto-start on boot

Windows spare-PC option

    - Task Scheduler -> Create Task -> Trigger "At startup"
    - Action: Start a program -> node -> arguments "server.cjs"
      starting directory = this project folder
    - Or use NSSM (free):  nssm install crayvings <node.exe path> server.cjs

12. BACKUPS + MONITORING (FREE)
================================================================================

PostgreSQL database backup - daily cron

Create /home/<user>/backup.sh (Linux):

    #!/bin/bash
    export PGPASSWORD="<strong-password>"
    DATE=$(date +%F)
    pg_dump -U crayvings -h localhost crayvings > \
        /home/<user>/backups/crayvings-$DATE.sql
    find /home/<user>/backups -name "crayvings-*.sql" -mtime +30 -delete

    mkdir -p /home/<user>/backups
    chmod +x /home/<user>/backup.sh
    crontab -e      # add this line (runs daily at 3am):
    0 3 * * * /home/<user>/backup.sh

    Copy the .sql files off-site occasionally (USB stick / cloud drive).

What's stored where (you do NOT need to back up raw sensor data forever):
    - The server already deletes sensors rows and system_logs older than
      30 days automatically (startup + once a day).
    - Still worth keeping the DB backup for settings, users, recipients,
      alert history and SMS logs.

Uptime monitoring (optional, free)
    - UptimeRobot.com free plan: add a monitor for
      https://your-dashboard.<something>.trycloudflare.com/health
      It emails/telegrams you if the site stops responding.
    - The app's own disconnect SMS already alerts you if the ESP32 goes
      offline (DEVICE_DISCONNECT_ENABLED=true).

15. APPENDIX - ESP32 NETWORKING NOTES
================================================================================

LAN-only (Option A / C at the farm)
    - The star topology expects its own LAN in the 192.168.4.0/24 range:
        192.168.4.1     access point / router (gateway + DHCP server)
        192.168.4.10    central server (backend + dashboard) - static IP
        192.168.4.100+  the ESP32 tanks (tank01..tank06)
    - Configure the router's LAN to that subnet BEFORE flashing any ESP32;
      the default ESP32 SoftAP range is 192.168.4.x, so using it for the LAN
      means the ESP32s never need NAT tricks.
    - Point the firmware at http://192.168.4.10:3000 (default) and give each
      tank its own device_id + optional static IP via the config portal.
    - Static IP method: the firmware's NVS static-IP fields (static_ip /
      static_gateway / static_subnet in the config portal) pin each device to
      192.168.4.100-105. Router DHCP reservations are an equivalent
      alternative - pick one per deployment and verify with GET /status.
    - Keep the DHCP reservation (if used) so the IP never changes, and
      remember to update the firmware if you change it.

Cloud (Option B)
    - SERVER_IP = your VM public IP or its domain; the ESP32 posts over the
      internet to /sensor on port 3000.
    - If you later lock the VM down behind the Cloudflare tunnel, the ESP32
      can instead POST to your public https:// URL (same path /sensor).
    - Confirm the farm/office router allows 3000 OUT - usually it does.

Device secret
    - Set DEVICE_SECRET (same value) in .env and in the firmware's
      X-Device-Secret (via the config portal field device_secret), otherwise
      the server refuses the POST.

Multi-tank / star-topology checklist (add to the LAN flow)
    [ ] Migration 007 applied: node db/migrations/007_multi_device.cjs
    [ ] devices.ip_address / tank_name / tank_location filled in for each ESP32
    [ ] ESPAsyncWebServer + AsyncTCP libraries installed in Arduino IDE
    [ ] Firmware flashed with per-tank device_id (tank01) + static IP + secret
    [ ] Router LAN = 192.168.4.0/24, gateway 192.168.4.1, server IP reserved .10
    [ ] GET /devices lists every tank; per-tank online flags flip correctly
    [ ] GET /devices/:id/status returns the device's live diagnostics
    [ ] Disconnect one tank -> its chip shows offline within ~15s and
        devices.last_health_seen stops advancing (server log: poller failure
        after 3 attempts); reconnect -> back to online
    [ ] Kill the server while a tank is running -> firmware buffer queues;
        restart the server -> queued readings flush oldest-first
