1. OVERVIEW
================================================================================

A web flasher allows end-users to flash/update ESP32 firmware directly from
the browser using the Web Serial API. No Arduino IDE, no Python, no CLI tools
required. The user simply connects the ESP32 via USB, selects firmware, and
clicks "Flash."

This is designed for end-user convenience - aquaculture operators who may not
be technical can update their ESP32 devices from the dashboard.

4. PREREQUISITES (MANUAL STEPS BEFORE IMPLEMENTATION)
================================================================================

The ESP32 firmware (esp32code/esp32code.ino) must be compiled into .bin files
before the web flasher can use them.

Step 1: Open esp32code/esp32code.ino in Arduino IDE

Step 2: Select Board
  - Tools > Board > ESP32 Arduino > "DOIT ESP32 DEVKIT V1"
  - (Or match your exact ESP32 DevKit board variant)

Step 3: Select Port (any COM port is fine for compiling)

Step 4: Compile
  - Sketch > Verify/Compile
  - Fix any compilation errors

Step 5: Export Compiled Binary
  - Sketch > Export Compiled Binary
  - This saves 3 files to the sketch folder:
      esp32code.ino.bootloader.bin    (offset: 0x1000)
      esp32code.ino.partitions.bin    (offset: 0x8000)
      esp32code.ino.bin               (offset: 0x10000)

Step 6: Copy the 3 .bin files into:
  public/firmware/

Step 7: Create public/firmware/manifest.json (see Section 8)

================================================================================
5. ESP32 FLASH MEMORY LAYOUT
================================================================================

The ESP32 uses a partitioned flash memory. The web flasher must write each
binary to the correct memory offset:

  Offset      Size       File                          Description
  ----------  ---------  ----------------------------  -------------------
  0x1000      ~28 KB     esp32code.ino.bootloader.bin  Bootloader
  0x8000      ~4 KB      esp32code.ino.partitions.bin  Partition table
  0x10000     ~1.3 MB    esp32code.ino.bin             Application firmware

  TOTAL: ~1.4 MB per flash

  NOTE: These offsets are for standard ESP32 (not ESP32-S2/S3/C3).
        The ESP32 DevKit V1 uses the standard ESP32 chip.

9. useEspFlaker HOOK API
================================================================================

The custom hook will expose:

  States:
    - status: "idle" | "connecting" | "connected" | "flashing" | "done" | "error"
    - progress: number (0-100)
    - logMessages: string[] (terminal output lines)
    - error: string | null
    - isSupported: boolean (WebSerial available)
    - chipInfo: { name: string, flashSize: string } | null

  Functions:
    - checkBrowserSupport(): boolean
        Returns true if Web Serial API is available

    - connect(): Promise<void>
        Opens the browser's serial port picker
        Connects to ESP32 ROM bootloader
        Reads chip info

    - flash(manifest): Promise<void>
        Erases flash (if selected)
        Writes bootloader to 0x1000
        Writes partitions to 0x8000
        Writes application to 0x10000
        Resets device

    - disconnect(): void
        Closes serial port cleanly

    - abort(): void
        Cancels ongoing flash operation (AbortController)

  Import:
    import { ESPLoader, Transport } from "esptool-js";

10. USER FLOW
================================================================================

  1. User logs into CRAYvings dashboard
  2. User clicks "Firmware Flasher" in sidebar
  3. Page loads and checks browser compatibility
     - If unsupported: show error + link to Chrome/Edge
     - If supported: show green checkmark
  4. User connects ESP32 via USB cable
  5. User clicks "Connect Device"
     - Browser shows serial port picker popup
     - User selects the ESP32 port (e.g., "USB-SERIAL CH340")
     - ESP32 connects and chip info is displayed
  6. User selects firmware (pre-built CRAYvings v1.0)
  7. User clicks "Flash Firmware"
     - Progress bar appears
     - Terminal output shows real-time progress
  8. If connection fails immediately:
     - UI shows instructions to enter download mode:
       "Hold the BOOT button on your ESP32, press and release
        the RST button, then release BOOT."
  9. Flash completes
     - Status: "Flash complete! Device is restarting."
     - Device automatically resets and starts running new firmware

11. ERROR HANDLING
================================================================================

  Error                           User-Facing Message / Action
  ------------------------------  ------------------------------------------------
  Browser not supported           "Web Serial API is not supported in your
                                  browser. Please use Chrome, Edge, or Opera."

  User cancels serial picker      "No device selected. Please try again."

  ESP32 not in download mode      "Could not connect to ESP32. Please hold the
                                  BOOT button, press and release RST, then
                                  release BOOT. Then try again."

  Serial port busy/locked         "Serial port is in use. Close any other
                                  programs using the port (Arduino IDE Serial
                                  Monitor, PuTTY, etc.) and try again."

  Firmware file invalid           "Invalid firmware file. Please select a
                                  valid ESP32 firmware binary."

  Chip mismatch                   "Expected ESP32 but detected {chipName}.
                                  Please select the correct firmware."

  Flash verification failed       "Flash verification failed. The device may
                                  not boot correctly. Try flashing again."

  USB cable issue                 "Could not detect device. Make sure you are
                                  using a data USB cable (not power-only)."

  Connection timeout              "Connection timed out. Check that the ESP32
                                  is properly connected and in download mode."

================================================================================
12. CONSTRAINTS
================================================================================

  - ESP32 DevKit V1 only (standard CP2102 or CH340 USB-to-UART chip)
  - USB cable required (not wireless/OTA)
  - Pre-compiled .bin files must exist in public/firmware/ before implementation
  - Chromium browser required (Chrome, Edge, Opera, Brave)
  - HTTPS required in production (Web Serial security requirement)
  - User must physically press BOOT button to enter download mode
  - No multi-device flashing (one ESP32 at a time)
  - Arduino IDE is needed for initial compilation (not for end users)

13. ALTERNATIVE APPROACHES CONSIDERED
================================================================================

  Option A: ESP Web Tools (esphome.github.io/esp-web-tools/)
    - Pros: Simplest to implement, uses <esp-web-install-button> web component
    - Pros: Automatic chip detection, manifest-based firmware selection
    - Cons: Limited UI customization, designed for ESPHome-style installs
    - Verdict: Too opinionated for custom firmware

  Option B: espcdcflash (USB CDC only)
    - Pros: Focused, clean API
    - Cons: ESP32-S3 only, does not support standard ESP32
    - Verdict: Wrong chip family for this project

  Option C: esptool-js (SELECTED)
    - Pros: Official Espressif library, full ESP32 support
    - Pros: Full control over UI and flashing behavior
    - Pros: Active maintenance, large community
    - Cons: More code to write for UI
    - Verdict: Best fit for custom React integration

  Option D: Standalone ESP-32-WebFlasher
    - Pros: Pre-built, works out of the box
    - Cons: Separate app, not integrated into dashboard
    - Cons: Hardcoded firmware list
    - Verdict: Not integrated enough for end-user experience
